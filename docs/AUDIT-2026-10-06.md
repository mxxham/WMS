# App audit — 6 Oct 2026

A full pass over the WMS for performance, bugs and missing features. Measured on
the local database and a local production build (`next build` + `next start`);
live has more history, so database timings there are higher.

## Summary

The core is solid: server-rendered pages answer in 10–150 ms locally, Vercel
(`sin1`) and Supabase (`ap-southeast-1`) are in the same region, Live
auto-refresh is debounced (1–5 s), and stock rules live in the database. The
gaps are error handling, a few silent data limits, page weight on phones, and
loose database permissions.

## Bugs and risks

| # | Finding | Impact | Fix |
|---|---|---|---|
| 1 | The Wave page runs 9 queries and checks none for errors (also Counts, Kualitas data, Receiving). | A Supabase hiccup shows "Belum ada rencana untuk tanggal ini"; a supervisor may re-run Alokasi. | Check each query's error; show "Gagal memuat, coba lagi". |
| 2 | No `error.tsx` anywhere. | Any server error is a blank "Application error" page (the 5 Oct dashboard crash). | One error boundary for `app/(app)` with the message and "Muat ulang". |
| 3 | 14 `SECURITY DEFINER` read functions are executable by `anon` (no login). Confirmed: `wms_stock_by_sku()` returns all 107 SKUs to an anonymous caller. | The anon key ships in the browser bundle: stock, FEFO and hold data are readable from the internet. | Revoke `execute` from `anon` on those functions. |
| 4 | Database timezone is UTC; 12 SQL places use `current_date`. | Receipts / putaway between 00:00 and 07:00 WIB get yesterday as GR date; `days_remaining` and the default recon date shift too. | Use `timezone('Asia/Jakarta', now())::date`. |
| 5 | `.range(0, 2999 / 4999 / 9999)` in 5 places; Supabase caps every request at 1,000 rows. | Putaway audit export silently drops rows past 1,000; Perbaiki semua over many SKUs can see incomplete stock. | Page with `fetchAll`. |
| 6 | `xlsx@0.18.5` has high advisories (prototype pollution / ReDoS); it parses uploaded files. | A crafted workbook could exploit the import. | Move to the SheetJS CDN build 0.20.3 (already planned in AGENTS.md). |

## Missing features

- SAP reconciliation measures WMS stock at upload time, not at the SAP extract time — the biggest source of false differences.
- No "bin empty?" / near-zero check when a pick empties a bin, so a wrong bin (CC25A01: system 3, real 1) is found late. *(Being added: see 0058.)*
- No variance Pareto (worst bins / SKUs / people) and no count-compliance KPI.
- No stock-opname mode (zone freeze, double count, final report, sign-off).
- No scheduled jobs: cycle-count planning and cleanup run only on a click.
- Check whether the Supabase plan has point-in-time recovery; without it a wrong import is undone only to the last daily backup.

## Minor

- `postcss` (via Next, build time) and `uuid` (via ExcelJS) advisories; fixed by normal upgrades.
- Koreksi picklist count tasks also appear in Perlu ditangani (duplication).

## Suggested order

1–3 first (small; they prevent wrong decisions and data exposure), then 4–5,
then 7–8 for phone speed, then 6.

## Done on 6 Oct (after this audit)

**Cek sisa bin (migration 0058, test 33).** After a Posting from the phone,
when the pick (or a pallet's Bin To Bin) leaves at most
`inventory_policy.bin_check_max_qty` cartons (default 5, 0 included) of that
SKU + batch in the bin, the dialog asks how many are left — blind, with a big
`Kosong (0)` button and `Lewati`. Every answer is logged in `bin_checks`; an
answer that differs from the system opens a count task on the bin
("Cek sisa setelah NO 8 #11: sistem 0, dilihat 2"). Stock is not changed by a
glance. The threshold is in Pengaturan.
